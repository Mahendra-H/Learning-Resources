What makes this series different
Not a certification course
Project-anchored from day one
Every concept is introduced in the context of the PingFederate migration project. You learn why a Launch Template exists because you need one to refresh AMIs. You learn S3 backends because your team already uses one.
Mentored progression
Each module earns the next
No module is self-contained. Each one builds a bridge to the next — explaining what knowledge you now have, what gap remains, and exactly why the next topic fills it. You will never wonder "why am I learning this?"
Your background is an asset
IAM expertise, applied to infra
Your deep IAM knowledge is a genuine advantage here. IAM roles, instance profiles, S3 bucket policies, and least-privilege design are concepts you already own. This series leverages that and fills the infrastructure gaps.
Real operational depth
Read code, fix things, ship safely
The goal isn't to write Terraform from scratch on day one — it's to confidently read existing code, understand why decisions were made, troubleshoot deployments, and eventually contribute improvements to a real enterprise codebase.
Your learning path
Phase 0 — Foundation & Mental Model
1 module · ~3–4 hrs
M01 3–4 hrs
Infrastructure as Code & The Terraform Mental Model
Why IaC exists. Where Terraform fits in the four-component pipeline. HCL orientation. Validate and sharpen your existing understanding of the migration project before a single line of Terraform is written.
Anchor: GitHub Actions → Terraform → Ansible → PingFederate
→
Phase 1 — Core Language & State
2 modules · ~8–10 hrs
M02 4–5 hrs
HCL Fundamentals
Providers, resources, data sources, variables, outputs, local values. Learn to read any .tf file confidently — including the dynamic AMI lookup pattern your project uses to find the latest approved AMI at plan time.
Anchor: Dynamic AMI ID lookup · Security group definitions
→
M03 4–5 hrs
State Management
The most important concept in Terraform. State file anatomy, remote state on S3, DynamoDB locking, drift detection, resource import, and state surgery. Understand what happens to state when an ASG replaces an instance during an AMI refresh.
Anchor: S3 remote backend · Instance refresh state behaviour
→
Phase 2 — AWS Infrastructure, Layer by Layer
5 modules · ~20–24 hrs
M04 4–5 hrs
VPC, Subnets & Security Groups
VPC CIDR design, public/private subnets, route tables, IGW, NAT gateway, security group rules, and SG-to-SG references. Why the network layer is always provisioned before compute — and how PingFederate's network topology is expressed in Terraform.
Anchor: PingFederate port rules · Private subnet ASG placement
→
M05 3–4 hrs
IAM & Instance Profiles
Your IAM expertise applied to infrastructure. Trust policies, permission policies, instance profiles. The IAM role that allows EC2 instances to read PingFederate config from S3 — why it exists, what it contains, and how Terraform creates and attaches it.
Anchor: PF-to-S3 read role · Least privilege in instance profiles
→
M06 5–6 hrs
EC2, Launch Templates & Auto Scaling Groups
The heart of immutable infrastructure. Launch Template anatomy, AMI data source lookups, user_data bootstrap scripts, ASG desired/min/max, health checks, lifecycle hooks, and instance_refresh. How a Terraform plan triggers a rolling AMI replacement.
Anchor: AMI refresh workflow · user_data pulls PF config from S3
→
M07 4–5 hrs
Load Balancers & Route53
ALB vs NLB decision criteria for PingFederate workloads. Target groups, listeners, health checks, and how the load balancer keeps traffic flowing during instance refresh. Route53 hosted zones, A records, and alias records — the full DNS-to-node path in Terraform.
Anchor: NLB for TLS passthrough · Traffic continuity during refresh
→
M08 3–4 hrs
S3 & Config Externalisation
S3 bucket provisioning, policies, versioning, and encryption. Why S3 is the right persistence layer for immutable compute. The config externalisation pattern that lets PingFederate nodes be replaced without losing configuration — and how Terraform models the storage layer that makes it possible.
Anchor: PF config bucket · The pattern that makes instance replacement safe
→
Phase 3 — Enterprise Terraform
2 modules · ~8–10 hrs
M09 4–5 hrs
Modules & Enterprise Patterns
Reusable modules, module structure, versioning, and the Terraform Registry. Dev/Test/Prod environment management — directory-per-env vs workspaces. DRY patterns. How to navigate an unfamiliar enterprise Terraform codebase on day one without getting lost.
Anchor: Multi-env PF deployment structure · Reading existing enterprise code
→
M10 4–5 hrs
Troubleshooting & Operations
Reading Terraform plans like a senior engineer. Debugging failed applies. State incidents, dependency problems, and resource ordering. The AMI refresh end-to-end with failure scenarios. Zero-downtime patterns, rollback strategies, and operational runbooks for enterprise deployments.
Anchor: AMI refresh failure modes · What to do when plan surprises you
→
Capstone — Build the Full Stack
Standalone · ~4–5 hrs
★ CAPSTONE 4–5 hrs · Standalone reference
Build the PingFederate AWS Stack from Scratch
A guided self-build challenge that takes you from empty directory to a fully provisioned, production-pattern PingFederate environment on AWS. VPC → Security Groups → IAM → S3 → Launch Template → Auto Scaling Group → NLB → Route53. Each section is a challenge block with hint toggles and solution reveals — you write the Terraform, guided by meaningful prompts, not handed the answers. Completes with a 25-point enterprise readiness checklist so you know exactly when you're ready to contribute to the real project.
Anchor: Full AMI refresh workflow · Enterprise readiness checklist · Complete annotated architecture
