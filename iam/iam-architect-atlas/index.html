🧱 The One Diagram That Ties Everything Together

Every module in this portal maps back to the same layered model — the Enterprise Identity Stack. Think of it like the OSI model, but for identity systems. Each layer depends on the one below it, each has its own failure modes, its own security perimeter, and its own architecture decisions. When a concept feels abstract, anchor it here first: which layer of the identity stack am I actually talking about?

👤 Applications & Portals ↓ 🔐 SSO & Federation ↓ 🎫 Token & Protocol Layer ↓ ⚖️ Authorization Engine ↓ 📋 IGA & Lifecycle ↓ 🏦 PAM & Privileged Identity ↓ 📂 Directory & Identity Stores ↓ 🌐 Network & Infra Auth ↓ ☁️ Cloud & Machine Identity
🔵 Why this stack shape will feel familiar
You've seen this shape before — every time you've drawn a data flow from a user's browser login, down through PingFederate's SAML assertion, down through PingDirectory's LDAP lookup, down through Active Directory's Kerberos ticket, all the way to the VPN's RADIUS handshake. That is this stack. What this portal does is teach you the architectural name, the design pattern, and the failure mode at each layer — so you can reason about the whole system, not just the layer you're currently configuring. 📍

🧭 How To Use This Portal (Pick Your Path)

Built to be used like a reference library as much as a course — read in sequence the first time, then return module-by-module before design reviews, architecture discussions, or vendor evaluations. Two honest paths through the material:

🐇 The Architect's Fast Track
~20–24 hours total

Read each module's architecture diagrams, the callout boxes 🔵🟠🟢🟣, the "Key Takeaways," and the "Architect's Cheat Sheet" sections. Skip the deep-dive sequence diagram walkthroughs on first pass. You'll come away with the mental model and design vocabulary for every domain. Ideal if you're preparing for architecture discussions in the near term.

🐢 The Principal Engineer's Full Tour
~40–50 hours total

Every diagram, every sequence flow, every deep dive, every knowledge check, every enterprise case study. Best if you're building toward Principal Engineer or IAM Architect roles and want to internalize the design reasoning, not just the vocabulary. Four to six focused weekends; it doesn't feel like homework if you already care about this stuff. ☕

💡 Tip: the dark/light toggle in the top-right works on every module page — pick whichever is easier for long reading sessions. Both themes are fully designed, not afterthoughts. The callout color system (🔵 concept / 🟠 architecture / 🟢 engineer's-take / 🟣 security) is your navigation compass throughout all 16 modules.
