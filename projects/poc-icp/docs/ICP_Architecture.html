Agent Behaviour
ICP Outcome
Audit Event
ALLOW
0–25

code

enforce_decision() — The Decision Code

class Posture(str, Enum):
    ALLOW = "allow"  |  CAUTION = "proceed-with-caution"
    REQUIRE_APPROVAL = "require-approval"  |  DENY = "deny"

def enforce_decision(decision, approval_fn=None):
    match decision.posture:
        case Posture.DENY:
            emit_audit(decision, outcome="blocked")  # always fires first
            alert_siem(decision)
            raise TaskDeniedError(decision.reasons)   # hard stop

        case Posture.REQUIRE_APPROVAL:
            approved = approval_fn(f"Approve: {decision.action}?") if approval_fn else False
            if not approved:
                raise TaskDeniedError("Approval not granted")
            emit_audit(decision, outcome="approval-granted")

        case Posture.CAUTION:
            inject_caution_to_prompt(decision)  # shifts LLM reasoning toward hedging
            emit_audit(decision, outcome="completed-with-caution")

        case Posture.ALLOW:
            emit_audit(decision, outcome="completed")  # green light

interface IdpConnector {
  name: string
  getIdentity(upn: string): Promise<Identity>          // who is this user
  getRiskSignals(upn: string): Promise<RiskSignals>    // what risk signals exist right now
  getEntitlements(upn: string): Promise<Entitlements>  // what are they allowed to do
  getSessionHealth(token: string): Promise<SessionHealth> // how clean is the session

Risk Scoring Model — 7 Weighted Signals → 0–100 Score

Location anomaly
+25
any IdP · session data
New city or country vs user baseline. Strongest single predictor of account compromise. Ex: Priya (Mumbai) logs in from Singapore.
Privilege escalated recently
+20
any IdP · role events
JIT elevation in last 60 min dramatically expands what agents can reach. Ex: Finance-Admin-Temp granted 22 min ago.
MFA age > 60 min
+15
any IdP · session
Stale MFA means human may not be at keyboard. Long-lived sessions in automated agent workflows are high risk.
Chain depth ≥ 3 hops
+15
ICP chain tracker
3+ agent hops from human with no checkpoint = high accountability risk. Orchestrator → sub-agent → sub-sub-agent.
Device non-compliant
+10
Entra / Keycloak
Unmanaged or non-compliant device breaks zero-trust device posture assumption. Intune signal.
CA policy non-compliant
+10
Entra / Keycloak
Conditional Access policy violations override other signals. Forces re-evaluation even for low-score sessions.
Concurrent sessions > 5
+5
ICP session tracker
Unusual parallelism may indicate automated credential misuse. 5+ simultaneous agent sessions under one UPN.

perf

Performance Architecture — <150ms p95 at 200 Concurrent Sessions

Key optimisations
1.Parallel fan-out — Promise.all() to all connectors simultaneously. Total = max(IdP latencies), not sum. Critical path optimisation.
2.Risk-proportional TTL — Low risk sessions cached 300s. High risk sessions re-evaluated every 60s. Deny never cached.
3.Webhook invalidation — Authentik/Ping push auth events. Cache evicted immediately on risk state change. No stale posture.
4.Circuit breaker — ICP unreachable after 500ms → deny-by-default or last cached posture. Never blocks the agent chain indefinitely.
5.Service account caching — Connector auth tokens cached with renewal headroom. Connector calls never blocked by token refresh.
Deployment footprint
SIDECAR MODE (Phase 1)
1:1 with agent host pods. stdio MCP transport. 256MB RAM / 0.5 vCPU per instance. Scales automatically with agent pods.
CENTRALISED MODE (Phase 2)
Shared service behind mTLS API gateway. Shared Redis cluster. HPA on CPU + p95 latency metric. >50 concurrent agent sessions.
YOUR PC (local dev)
Intel Ultra 7 + 32GB RAM + RTX 500. Full stack: ~11GB RAM. Ollama Llama 3.1 8B with CUDA GPU offload. Comfortable headroom.
