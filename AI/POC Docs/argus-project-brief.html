01 The problem we are solving

Enterprises run Ping + EntraID + Saviynt + CyberArk as four separate silos. When an AI agent misbehaves, none of them talk to each other.

ToolWhat it holdsWhat it cannot doArgus open-source equivalent
CyberArkAgent secretsNo behavioral context — rotates on schedule, not on anomalyHashiCorp Vault
SaviyntIdentity lifecycle & entitlementsCannot trigger CyberArk rotation automaticallyKeycloak
Ping IdentityRuntime auth & risk signalsCannot revoke Saviynt entitlement on anomalyOry Hydra + Kratos
EntraIDApp registration & tokensUnaware of Ping risk signalsAuthentik
Argus is the event bus and orchestration layer that connects these four signals into one coordinated response. Not a replacement — a bridge.

10 Spec driven development with Claude

SDD solves all four Claude limitations — no memory, no code execution, no product decisions, code review burden — in one approach.

LEVEL 01
Project spec
Written once. What Argus is, what it is not, core entities, all technology decisions locked. The north star.
LEVEL 02
Module spec
One per feature area. Data contracts, API contracts, behavior rules. Written before building that module.
LEVEL 03
Task spec
Per coding session. Paste to Claude at session start. Precise enough for correct code on first attempt.
Claude limitationHow SDD solves it
No memory across sessionsCONTEXT.md + module spec = full context in every session. Gap of 2 weeks does not matter
Cannot run your codeSpec defines expected behavior upfront. Debugging = comparison against spec, not guessing
Cannot make product decisionsDecisions made during spec writing — locked before Claude touches a keyboard
Code needs reviewReview becomes mechanical — does code match spec contract? Yes or no
Session ritual — every time
1. Update CONTEXT.md — what was built, what is needed today   2. Open relevant module spec   3. Write task spec (10 min)   4. Paste all three to Claude   5. Run code, paste errors back   6. Update CONTEXT.md before closing
