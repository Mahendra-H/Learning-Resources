What ICP is

One MCP tool call

Any AI agent — CrewAI, LangGraph, AutoGen — calls get_identity_context() before acting. ICP queries all configured identity providers in parallel and returns a unified context payload: who you are, what you can do, how risky this session is, and what posture to apply.

Plug-and-play IdP design

Every identity provider implements the same IdpConnector interface. Swap Keycloak for Entra by changing one line in icp.config.json. No core code changes. Community can contribute connectors. ICP works with any enterprise identity stack.

Risk-aware, not just block/allow

Agents receive allow, proceed-with-caution, require-approval, or deny — and act proportionally. Caution mode injects security context into the agent's reasoning prompt. Agents self-moderate without hardcoded rules.

Full audit trail

Every agent action produces a structured audit event: user, agent_id, posture, outcome, risk_score, chain_depth, posture_reasons. The CISO can answer "what did our AI agents do last Tuesday?" with a single query on the audit log.

The airport analogy

Entra ID = Terminal A security guard (Microsoft workloads). Ping Identity = Terminal B security guard (web apps). Neither terminal knows what the other is doing. The AI agent checks in separately at each terminal with a static token — no unified picture of trust, risk, or current session health.

ICP = Air Traffic Control. One real-time view across all terminals. Every agent, every session, every risk signal — unified before any action is taken.

Problem Statement

Three identity blind spots that exist in every enterprise AI deployment today

The three blind spots

No cross-IdP signal sharing

A privilege escalation in Ping is invisible to Entra-protected resources. Neither IdP surfaces the other's risk signals to AI agents in real time. Agents act on partial identity pictures.

Agents carry static tokens

AI agents receive a token and act on it — zero awareness that the user's session risk changed 5 minutes ago. Location anomaly, stale MFA, device compliance change — invisible to the acting agent.

No chain accountability

When a CrewAI orchestrator spawns 4 sub-agents, nobody records which human authorised them, what their risk was at authorisation time, or what action each agent took. Zero audit trail for automated chains.

Why Ping and Entra won't close this gap

Competitors don't cross-integrate

Ping and Entra are direct competitors. Ping will never build deep Entra signal fusion, and Microsoft will never surface Ping risk signals natively. ICP is vendor-neutral by design — it sits above both and reads from either.

Neither has agent framework depth

CrewAI, LangGraph, and AutoGen don't have identity. Identity vendors don't have agent framework depth. ICP lives at exactly that intersection — and it's the only place these two worlds can meet cleanly.

Market timing: MCP launched Nov 2024 — estimated 90%+ enterprise adoption within 12 months. Ping shipped Mar 2026. Entra shipped May 2026. The market just validated the problem is real and enterprises will pay. The cross-IdP fusion window is open right now.

Pluggable connector interface
// Every IdP — Keycloak, Entra, Ping, Okta, Auth0, Cognito — implements this one interface
interface IdpConnector {
  name: string;                                           // "keycloak" | "entra" | "ping" | "okta" ...
  getIdentity(upn: string): Promise<Identity>;             // who is this user
  getRiskSignals(upn: string): Promise<RiskSignals>;      // what risk signals exist right now
  getEntitlements(upn: string): Promise<Entitlements>;   // what are they allowed to do
  getSessionHealth(token: string): Promise<SessionHealth>; // how clean is the session
}

// Aggregator is IdP-agnostic — receives an array, doesn't care where data came from
const contexts = await Promise.all(
  activeConnectors.map(c => c.getIdentity(upn))
);
return aggregate(contexts);

Hot-reload + dev overrides

Risk weight hot-reload

ICP watches icp.config.json for changes using fs.watch(). Risk signal weights and posture thresholds update without restart. Security teams tighten posture live during an incident — no redeployment.

Dev mode overrides (env vars)

ICP_DEV_POSTURE=deny — force posture for all calls
ICP_DEV_SCORE=85 — force risk score
ICP_DEV_CONNECTOR=mock — bypass real IdPs

Test any branch without engineering specific IdP states.

Startup validation (Zod)

Every config field validated at boot

The entire icp.config.json is parsed through a Zod schema on startup. Invalid config prints a specific, human-readable error — field name, expected type, received value — then exits cleanly. Never a cryptic runtime crash mid-request.

enforce_decision() — the decision code
class Posture(str, Enum):
    ALLOW           = "allow"
    CAUTION         = "proceed-with-caution"
    REQUIRE_APPROVAL= "require-approval"
    DENY            = "deny"

def enforce_decision(decision: ICPDecision, approval_fn=None) -> None:
    match decision.posture:
        case Posture.DENY:
            emit_audit(decision, outcome="blocked")
            alert_siem(decision)
            raise TaskDeniedError(decision.reasons)

        case Posture.REQUIRE_APPROVAL:
            approved = approval_fn(f"Approve: {decision.action}?") if approval_fn else False
            if not approved:
                emit_audit(decision, outcome="approval-denied")
                raise TaskDeniedError("Human approval not granted")
            emit_audit(decision, outcome="approval-granted")

        case Posture.CAUTION:
            inject_caution_to_prompt(decision)  # shifts LLM toward hedging
            emit_audit(decision, outcome="completed-with-caution")

        case Posture.ALLOW:
            emit_audit(decision, outcome="completed")  # green light

They then edit one line in icp.config.json — change location_anomaly weight from 25 to 0 — rerun — score drops below deny threshold — agent proceeds. They understand the entire system from that one interaction.

Why ICP doesn't compete with Ping or Entra

ICP does not replace Ping or Entra. It makes the investment in both significantly more valuable in an AI-agent world. Every Ping customer who deploys ICP gets Entra signal visibility for the first time — and vice versa. ICP is the layer that connects what already exists. That's the sales story to enterprise security teams.
