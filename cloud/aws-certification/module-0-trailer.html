Scene 04.5 — Cracked Open

This is what an exam question actually feels like

Not a definition to memorize — a judgment call under pressure. Here is one, in the exact rhythm every module in this course drills.

Scenario

A GuardDuty finding shows unusual overnight S3 API activity from an EC2 instance whose role was granted s3:* across all buckets "temporarily," months ago, for a migration that finished. Other production workloads run under separate roles on the same subnet. What is the best immediate action?

ATerminate the EC2 instance immediately to stop the activity.
BRevoke the instance's active credentials and attach a restrictive policy, preserving the instance for forensics.
CDelete the S3 buckets the instance has been accessing.
DWait for Security Hub to auto-remediate the finding.

Why B, specifically

Containment has to come before cleanup. Revoking the instance's temporary credentials (or detaching the role) stops the bleeding instantly, without destroying the instance — which is your evidence. Terminating first (A) is the classic trap: it feels decisive but destroys the forensic trail you need for the incident report.

Why the others fail

C punishes the data instead of the access path, and still leaves the over-permissioned role live elsewhere. D assumes automation that was never configured — GuardDuty detects, it does not remediate on its own.
